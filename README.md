# Лаборатория графов взаимодействий

Проект к семинару по КИТГ: анализ социальных сетей, графы подписок, репостов и упоминаний,
меры центральности и каскады распространения информации. Соответствует частям I–III доклада.

**Соглашение о направлении.** Ребро `u → v` означает, что `u` обращает внимание на `v`
(подписан, репостит, упоминает). Сообщения идут против стрелок: от автора к подписчикам.

## Состав

| Путь | Что делает |
| --- | --- |
| `sgl/graph.py` | ориентированный взвешенный граф на разреженных матрицах |
| `sgl/higgs.py` | загрузка набора Higgs (SNAP), слои на общем множестве вершин, проверка направления |
| `sgl/extract.py` | этап 2: связи из текста (`RT @имя:`, `@имя`, ответ), точность и полнота |
| `sgl/measures.py` | восемь мер: степени, близость, посредничество (Брандес), собственный вектор, PageRank, HITS, k-ядра |
| `sgl/cascade.py` | модели IC, WC, LT; общие случайные числа; точное σ(S) перебором для проверки |
| `sgl/service.py` | логика веб-сервиса (кэш в памяти, без базы данных) |
| `app/` | FastAPI и страница на чистом JavaScript (без внешних библиотек и без CDN) |
| `scripts/compute_metrics.py` | таблица «вершина × мера» для слоя Higgs, проверка направления рёбер |
| `scripts/run_experiments.py` | эксперименты 1–4 из части III (на учебной сети или на слоях Higgs) |
| `results_synthetic.json` | результаты экспериментов на учебной сети (1500 вершин) |
| `tests/` | 43 теста: значения G1 и G2 из теории, сверка с NetworkX, свойства каскадов |

## Запуск в Docker

```
docker build -t graph-lab .
docker run --rm -p 8000:8000 -v "$PWD/data:/data" graph-lab
```

Откройте http://localhost:8000. Без каталога `data` работают три учебных графа и загрузка
собственного списка рёбер. Если в `data` лежат файлы Higgs (см. `data/README.txt`),
слои появятся в списке наборов. База данных и авторизация не используются.

## Запуск без Docker

```
pip install -r requirements.txt
SGL_DATA_DIR=./data uvicorn app.main:app --port 8000
```

## Тесты

```
pip install -r requirements-dev.txt
python -m unittest discover -s tests -t .
```

Тесты проверяют значения из части I: посредничество 14, 12, 10 в G1, PageRank
0,282 / 0,272 / 0,270 / 0,146 / 0,030 в G2, средний размер каскада 1,75 на цепочке,
а также монотонность и убывающую отдачу σ(S) точным перебором.

## Набор Higgs из командной строки

```
python scripts/compute_metrics.py --data ./data --layer retweet --out retweet_metrics.csv
python scripts/compute_metrics.py --data ./data --layer social --skip-paths --check-direction
```

Перед расчётами выполните `--check-direction` и сверьте число вершин и рёбер с описанием
набора на странице SNAP. Формат строк в файлах принят по описанию набора («A B» и
«A B вес»); если он отличается, поправьте `read_edgelist` в `sgl/higgs.py`.

## Эксперименты

```
python scripts/run_experiments.py --n 1500 --out results.json                      # учебная сеть
python scripts/run_experiments.py --data ./data --layer retweet --skip-timing         # слой Higgs
python scripts/run_experiments.py --data ./data --layer social --skip-paths --skip-timing
```

Эксперимент 2 выполняется, если в `--data` есть слои social и retweet и выбран слой social.

## API

| Запрос | Назначение |
| --- | --- |
| `GET /api/sources` | список наборов данных |
| `POST /api/analyze` | граф, все меры, рёбра для рисунка (до 400 вершин с наибольшим PageRank) |
| `POST /api/cascade` | одна симуляция каскада по шагам |
| `POST /api/compare` | лучшие по мере против случайных, одни и те же «миры», доверительный интервал |
| `POST /api/quiz` | проверка ответа в режиме тренажёра |

## Ограничения

* Близость и посредничество считаются на Python. До 400 вершин расчёт точный, до 5000 по
  выборке из 150 начальных вершин, для больших графов не вычисляются. Полный граф подписок
  Higgs (около 14,9 млн рёбер) для этих двух мер требует компилируемого кода или долгого ночного расчёта.
* Остальные меры (степени, PageRank, HITS, собственный вектор, k-ядра) на полном графе
  считаются на разреженных матрицах.
* Раскладка вершин для рисунка считается в браузере и рассчитана на сотни вершин.
* Версии библиотек в `requirements.txt` заданы нижними границами; после первой удачной
  сборки зафиксируйте точные версии (`pip freeze`).
